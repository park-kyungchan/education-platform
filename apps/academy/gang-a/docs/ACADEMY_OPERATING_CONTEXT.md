# Academy operating checkpoint

`context/academy/checkpoint.json` is the common, repo-native operating catalog, schema `academy.operations/1.1.0`. It includes the completed common-policy interview as of 2026-10-08, in Asia/Seoul. Future source checks, case follow-ups and explicit deferrals remain separate. Unresolved and deferred work remains unresolved and deferred. Its documents, role descriptions, recurrence and action specifications do not grant runtime execution authority.

## Ownership and typed relationships

The graph contains one academy root, four domains, 71 policies, ordered steps, roles, artifacts, concepts and references. Typed edges connect containment, step order, dependencies, responsibility, reporting, artifact production, methods and reference use. Only containment, ordering, dependencies and source supersession must be acyclic; conceptual relatedness may form a cycle. Independent knowledge, lifecycle, obligation, applicability and automation states prevent recommendations, expired announcements and conditional assignments from becoming present duties.

`packages/domain/operational-context.ts` holds strict schemas and branded operating IDs. It shares the existing evidence actor/reference primitives, Instant and SHA contracts. Existing student EvidenceScope, Evidence, Decision and HTTP wire versions retain their student responsibilities; no academy policy receives a fictitious student. Existing book, assessment, assignment, delivery and teacher-outcome concepts are linked as domain references. Real student entity/edition bindings still require separate student evidence.

`packages/application/validate-operational-context.ts` verifies references, source/file pins, graph kinds, ordered steps, reciprocal investigation joins, coverage, deferral and selected semantic boundaries. `selectOperationalContext` returns a deeply frozen, revision-pinned task view with ancestors, dependencies, relevant evidence, structured practice and superseded history. `planOperationalAction` prepares that view and returns `executionAllowed=false`. It performs no communication, scheduling, submission, system entry or physical action.

Inspect relevant policies, rather than injecting the entire catalog into each task:

```sh
bun inspect-operational-context.ts D-A02
bun inspect-operational-context.ts D-A04 D-A15
bun run lint
bun run validate
```

The local inspection command uses the checked-out manifest. The repository adapter requires an independently trusted manifest byte hash from its caller, then verifies the exact catalog byte hash and length. A document-supplied pin or locator is not authority. This adapter reads these fixed repository files only and introduces no network or deployed backend.
