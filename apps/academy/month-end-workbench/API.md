# Month-end application contract

`src/contracts.ts` is the browser-safe stable contract. `src/application.ts` exports `createApplication(projection, sourcePort?)` with asynchronous `context()`, `research({typeId})`, `navigate(pathIds)`, `study(report)`, `intent(intent)`, `sourceScope(request)`, `find(request)`, `review(request)`, `snapshot()` and `setScope(scope)`. A research-only default is unavailable, never synthetic fallback. `src/research.ts` exports the committed pinned `researchProjection`. UI can use identical application logic locally or use the HTTP adapter.

HTTP: GET `/api/state` (ApplicationState snapshot), `/api/context`, `/api/research?typeId=...`, `/api/navigation?path=U-M,HM1,...`; POST `/api/study-scope` (StudyScope, updates research scope), `/api/study`, `/api/intent`, `/api/scope`, `/api/find`, `/api/review`, `/api/alignment` (AlignmentProposalRequest→AlignmentProposal). JSON payloads use contracts above. GET `/api/session` returns `{csrfToken}`; all POSTs must have `x-month-end-csrf` and exact same Origin. `/api/scope` uses SourceScopeRequest (Academy traversal), not StudyScope. Mutation results study/intent/study-scope return ApplicationState; navigation returns NavigationResult. Ephemeral study/intent state is session-bound; responses include no final membership. `createRequestHandler({applicationFactory, allowedOrigin, frontendRoot?})` is exported from `src/server.ts` for synthetic tests. All API responses use `{ok:true,data}` or `{ok:false,error}`. The GET context response is `AssessmentContext`.

`SourcePort` is injected server-side; adapter-owned namespace validation cannot be delegated to a browser. Find/review carry exact SourceContext + explicit scope-bound teacher StudyReport and DesiredQuestionIntent. Application independently checks these against session state, denies source-context drift, foreign namespace/owner and absent source/study bindings. Labels use `pat_no`, questions use `lecture_key`; neither is research identity. All comparison candidates remain held/provisional. Source reviews are bounded original question pages, not exam selections. No persistence, finalization, printing, generation or send route exists.

Source importer: `bun run source:verify -- /absolute/clone` verifies the exact immutable revision and every pinned source hash, then compares deterministic projection output. `bun run source:import -- /absolute/clone` only rewrites identical pinned projection, never regenerates pins. Normal check/build use committed safe data and no credentials.

Async source reads capture a dependency epoch and recheck exact current study/intent/source binding after transport completes. Changed dependencies hold stale results before history/publication. Scope traversal publishes only the latest in-flight traversal; older out-of-order results are refused.

`alignmentProposal(request)` creates only an ephemeral teacher-proposed Research↔Academy review memo. Request uses current context/study/intent/pat_no and six exact axes `{state:'unknown'|'supports'|'conflicts',note,questionRefs:[{lecture_key,sourceRevision}]}`. Supports/conflicts require a note and inspected exact question revisions. Caller hashes/authority/acceptance fields are forbidden. Backend derives research refs and question evidence hashes from already validated current-scope reviews. Question digests describe the returned validated projection, not original publisher bytes or acquired full content. Result is AlignmentProposal with `proposal_not_accepted`, `teacher-proposed`, `acceptance:false`, `finalMembership:false`. `/api/state` includes alignmentProposals; dependency changes mark old proposals historical without deletion.
