# Academy MCP source port

`createMcpSourcePort(undefined, projection)` remains unavailable and starts no process. This module is server-only; launch configuration, bridge files and native records do not belong in frontend/static bundles.

## Configured subprocess launch is held

The factory synchronously clones, validates and deeply freezes the complete executable, bundle and source configuration before any asynchronous pin read. It checks selected bytes through bounded descriptors without following symlinks. Those checks are diagnostics only: every configured mode, including a synthetic subprocess, then refuses with `mcp_verified_execution_boundary_unavailable`.

The installed official SDK stdio transport launches executable/script paths. It exposes no supported verified-descriptor or sealed-artifact handoff in this integration. Closing a verified descriptor and later launching a pathname permits replacement of the executable, bundle, bridge or snapshot. A last-second hash reread or an unchecked temporary copy does not close that execution race. This implementation therefore never creates that transport or launches configured paths. It adds no native installer, credential getter, trust/config mutation or alternative child launcher.

Native-read mode in `main.ts` stays held until a separately reviewed owner supplies a sound verified-artifact execution boundary. Previous live-read receipts remain historical engineering evidence for their original source; they do not qualify this successor's native launch. No current end-to-end native consumption, teacher acceptance or production readiness is claimed.

## Explicit in-process synthetic engineering

`createSyntheticMcpSourcePort(client, projection)` consumes a caller-connected in-process synthetic SDK client. It captures the three client callbacks before awaiting and owns a frozen projection copy. It selects synthetic mode only; `main.ts` never creates it from JSON, launch configuration or a browser request. The caller owns fixture creation/connection and cleanup. The normal research-only backend remains unavailable, and the separate domain synthetic mode remains explicit.

Tests pair the official client and server through a test-only memory transport. The owned Academy `registerItemLabelTools`/`registerDailyRecordTools` functions are also tested with a fictional `ItemLabelIndex`; the owner CLI entrypoint, native bridge and credential paths are not run. Select the intended maintained Academy source using `MONTH_END_QA_ACADEMY_MCP_ROOT` (or the documented sibling fallback) before running these source-only checks. No implementation is copied from that owner.

Only `academy_item_label_scope`, `academy_find_item_labels` and `academy_review_type_questions` are called. DailyRecord/CISM tools may be discovered but are never called. Every response must echo the exact research revision, source pins, current source context, study report and desired axes with a digest. This is task binding, not authenticated native proof or permission. Research IDs, `pat_no`, `lecture_key`, paper keys and `q_code` remain separate namespaces.

Pages of the same source receipt retain opaque handles/cursors; changed receipts remain distinct. Unknown edition/unit metadata stays null and permits only explicitly provisional comparison; known differences hold. Blank, malformed, absent or unsafe count metadata remains unknown rather than becoming zero. Explicit decimal zero remains zero. Six mathematical axes remain provisional and require inspected evidence for a teacher proposal; no final membership, generation, save, send or image export is added.

Verification consists of finite synthetic SDK/domain/HTTP checks and adversarial configuration/path-replacement tests. It does not establish actual native authentication/source reads, mathematical or pedagogical acceptance, learning effects, or production integration.
