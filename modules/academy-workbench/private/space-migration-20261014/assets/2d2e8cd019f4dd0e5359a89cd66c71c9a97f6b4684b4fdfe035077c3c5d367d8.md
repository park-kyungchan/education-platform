# 학원 전체 영역 조회 등록부와 검증 기준

13개 업무 묶음의 과거 클릭 관찰과 승인된 업로드 계약을 같은 조회 등록부로 연결했다. 32개 경로와 49개 독립 동작에서 어떤 근거를 재사용할 수 있는지, 어디까지 확인됐는지, 무엇을 더 검증해야 하는지 동일한 형식으로 찾을 수 있다. 실제 학원 서버 연결은 아직 없다.

업무 묶음 수는 사이트의 전체 메뉴 개수나 전체 기능 검증 완료를 뜻하지 않는다. URL이 확인된 경로는 26개이며, 일부는 초기 화면만 확인됐다.

## 현재 확인 수준

- 요청 캡처: StudentNameSearch POST 1개. 최근3주 필터의 27행 응답 구조만 확인됐다.
- 오프라인 파서: 별도 합성 HTML과 bootstrap 28개 검사 통과. 실제 HAR 학생 응답의 파싱 성공을 입증하는 검사는 아니다.
- 등록부: 37개 구조·범위·허위 승격 방어 검사 및 strict TypeScript 검사 통과.
- 현재 인증 연결, 실서버 읽기 검증, 실서버 결과의 저장 후 재읽기 검증: 모두 미확인.
- 이번 취합 과정의 학원 서버 요청, 사용자 PC 접근, 원본 HAR 학생 응답 읽기: 모두 0회.

## 검증 단계

각 단계는 별도의 근거를 요구한다. 앞 단계가 확인됐다고 다음 단계를 자동으로 확인 처리하지 않는다.

| 단계 | 확인되는 내용 |
|---|---|
| menu_observed | 실제로 보고된 화면/라벨/URL 관찰. 의미상 업무 묶음은 메뉴로 승격하지 않음 |
| ui_query_verified | 당시 제한된 UI 조회 순서·표시 결과가 관찰 보고에 있음. raw 재검증·HTTP·현재 성공 아님 |
| request_captured | 정확한 request method/params/encoding/response가 승인 업로드 캡처에 있음. read-sideeffect/auth는 별도 |
| offline_parser_verified | 별도 고정 테스트 receipt로만 검증. synthetic 시험과 실제 업로드 응답 parser pass 구분 |
| auth_connected | 현재 허용된 환경/계정의 인증·권한·세션 연결 receipt. 문서/HAR/코드 배포로 대체 금지 |
| live_read_verified | 현재 실제 서버 조회의 학생·범위·완료·시간·응답·효과 검증 receipt |
| published_verified | 현재 검증된 source 결과를 승인 목적지에 저장 후 scope·해시·버전 readback. UI code 배포 아님 |

과거 UI 관찰은 당시 전달된 보고에 근거한다. 정확한 클릭 시각이 없으면 null을 유지하고 보고 시각 또는 관찰 구간을 따로 보존했다. 2026년 10월 6일 06:33:49–06:44:20 UTC 구간도 개별 클릭 시각으로 쓰지 않는다. 업로드 캡처 시각 2026년 10월 7일 08:05:31.277 UTC는 실제 학습 사건 시각이나 이번 서버 조회 시각이 아니다.

## 학습결과 요청의 정확한 재사용 범위

정확한 URL은 https://dc.gang-a.kr/servlet/controller.tutor.base.TestPageListServlet?p_process=StudentNameSearch 이며 POST, application/x-www-form-urlencoded, UTF-8, HTTP 200 text/html이 캡처됐다.

본문의 관찰된 이름은 clg_no, book_code, stu_name, check_all_stu, sort_date, chioce_course이다. chioce_course는 실제 철자를 보존했다. 학생 값이나 실제 고정 form 값은 이 등록부에 넣지 않았다. HTTP 200만으로 인증 상태나 읽기 부작용을 검증할 수 없다.

testingNo, pNo, testNo, courseKey, _id는 관찰된 필드다. testingNo와 pNo의 유일성은 해당 27행 안에서 확인됐지만 안정된 네이티브 응시·종이 ID 의미는 미검증이다. onclick의 첫 인수는 목록 행 인덱스이며 네이티브 응시 ID로 사용하지 않는다.

최근3주 응답에서 특정 항목이 없다는 사실은 그 기간과 업로드 응답 범위의 부재만 의미한다. 전체 이력의 부재나 미수행으로 바꾸지 않고, 기존 44행 이력 정본을 대체하지 않는다.

다른 경로의 method, request parameter, body encoding, 응답 schema, 안정 ID, 인증과 read-sideeffect는 unknown이다. UI URL의 reqCmd 또는 p_process literal을 실제 API 계약으로 승격하지 않았다.

## 동작을 나누는 기준

DATA는 최소 대상 참조와 원문 관찰을 다룬다. LOGIC은 학생·판본·과제·시도·시간·범위의 일치를 검증한다. ACTION은 조회, 저장, 채점, 재응시, 자료 생성, 실제 인쇄, 공유와 발송을 각각 독립 작업으로 계획한다. SECURITY는 현재 사용자 의도와 대상, 계정 권한, 도구 상태, 승인 요건과 중단 조건을 확인한다. 등록부는 어느 작업의 실행권한도 부여하지 않는다.

- DT는 사용자가 확정한 DailyTest 수업활동이다. DailyRestudy 교재섹션은 별개 엔티티다.
- 교사 판단은 EvidenceRecord와 DecisionRecord를 독립 참조한다. 점수나 사이트 미학습 표시로 대신 생성하지 않는다.
- 오의 원래 오답과 클의 대응 유사문항, 행 제어와 상단 일괄 제어, 개별 수량 1과 일괄 설정 2의 과거 관찰을 구분한다.
- 과거 승인된 오 일괄 PDF 생성은 1회 실행됐고 외부 뷰어 열림을 사용자가 확인했다. 헤더·문항·페이지와 물리 인쇄는 확인되지 않았다. 같은 작업을 중복 생성하지 않는다.
- PDF 생성, 뷰어 열림, PDF 검증, 물리 인쇄, 배부, 수령과 학습 완료는 서로 다른 사건이다.
- 상담·학부모 안내·인수인계의 새로운 발송·자료 공유는 정확한 수신자와 내용, 목적과 승인 요건을 별도로 확인한다.

## 확장 방법

새 소스는 해당 sourceFamilyId와 routeId 아래에 추가하고, 동작마다 operationId를 부여한다. 메뉴나 업무 이름을 기반으로 요청 주소를 추정하지 않는다. 최소 범위의 승인된 요청·응답 캡처가 생기면 request_captured만 갱신하고, 파서 검사 receipt, 현재 인증 receipt, 실제 읽기 receipt와 목적지 재읽기 receipt를 각각 따로 연결한다.

새 학생은 공통 registry에 개인 결과를 복제하지 않고 선택된 비공개 namespace와 공통 판본·과제·근거 계약을 참조한다. 결과를 가져오지 못한 소스는 이전값과 lastSuccessAt을 보존하고 해당 소스만 부분 실패 또는 미조회로 표시한다.

기존 context-load registry에 있는 intent와 새 조회 제안을 구분했다. 새 이름이 등록됐다는 이유로 실행 경로나 필수 맥락 로딩이 자동으로 활성화되지는 않는다.

## 파일과 근거

- academy-capability-registry.v1.json: 13개 영역, 경로, 단계별 근거, unknown과 최소 갭의 정본
- capability-registry.ts: 타입, validateRegistry와 planArea의 오프라인 fail-closed lookup
- validation-receipt.json: 등록부 37개 검사 receipt. 실제 서버나 학생 응답 파서의 검증 receipt와 별개
- academy-offline-connector/validation.json: 합성 파서 28개 검사 receipt. source stage를 넘어 승격하지 않음

원래 업무·사이트·숙제·판본 계약과 canonical EvidenceRecord 및 DecisionRecord를 참조한다. 학생 개인 기록, 연락처, 답안, 실제 ID 값과 인증값은 공통 registry에 포함하지 않는다. 거부·취소됐던 비공개 상세 수집과 현지 감사 원문 읽기는 재시도하거나 다른 경로로 우회하지 않았다.
