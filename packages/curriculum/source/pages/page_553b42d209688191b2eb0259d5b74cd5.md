# 수학 객체와 관계 변경 계약

개념·용어·기호의 객체 정체성과 관계·변경의 계약을 분리합니다. 아래 내용은 자체 도메인 설계이며 Palantir 배포 설정이나 import 파일이 아닙니다.

## 객체 타입과 인스턴스

MathConcept는 타입이고 ‘통분’은 그 인스턴스입니다. 학년, 단원 목차, 설명의 깊이를 객체 타입의 상속 계층으로 만들지 않습니다. [공식 Object types](https://www.palantir.com/docs/foundry/object-link-types/object-types-overview)

| 객체 타입 | 최소 의미 필드 |
| --- | --- |
| MathConcept | id String · title String · definition String · revision Integer · curriculumMappingStatus Enum |
| MathTerm | id String · label String · language String · sense String |
| MathNotation | id String · expression String · interpretation String · scope String |
| Explanation | id String · conceptId ObjectReference · perspectiveId ObjectReference · body String · notCurricularPrerequisite Boolean |
| CurriculumStandard | id String · curriculumEdition String · officialCode String · gradeBand String · sourceUrl String · verificationStatus Enum |
| CurriculumAlignment | id String · conceptId ObjectReference · standardId ObjectReference · rationale String · approvalStatus Enum |
| Perspective | id String · audience String · explanationLevel Enum · pedagogicalRoute String |
| DependencyAssertion | id String · prerequisiteConceptId ObjectReference · dependentConceptId ObjectReference · relationKind Enum · claimBasis Enum · perspectiveId ObjectReference · conditions StringArray · rationale String · evidenceIds ObjectReferenceArray · approvalStatus Enum · revision Integer |
| EvidenceReference | id String · sourceUrl String · locator String · verificationStatus Enum |
| ChangeProposal | id String · assertionId ObjectReference · expectedRevision Integer · changes FieldChangeArray · reviewedPayloadHash String · approvalStatus Enum |
| RevisionEvent | id String · assertionId ObjectReference · fromRevision Integer · toRevision Integer · reason String · executionMode Enum |

공통 식별·계층·상태 필드까지 포함한 전체 레코드 형식은 연결된 JSON Schema에 있습니다. CurriculumStandard와 CurriculumAlignment는 계약만 정의했으며, 검증하지 않은 공식 성취기준 인스턴스는 생성하지 않았습니다.

## 관계 계약

| 관계 | 양쪽 탐색명 | 연결 수 |
| --- | --- | --- |
| MathConcept → MathTerm | namedBy / namesConcept | one_to_many |
| MathConcept → MathNotation | usesNotation / usedByConcept | one_to_many |
| MathConcept → Explanation | explanations / explainsConcept | one_to_many |
| DependencyAssertion → MathConcept | prerequisiteConcept / outgoingAssertions | many_to_one |
| DependencyAssertion → MathConcept | dependentConcept / incomingAssertions | many_to_one |
| DependencyAssertion → Perspective | perspective / dependencyAssertions | many_to_one |
| DependencyAssertion → EvidenceReference | evidence / supportsAssertions | many_to_many |
| CurriculumAlignment → MathConcept | concept / curriculumAlignments | many_to_one |
| CurriculumAlignment → CurriculumStandard | standard / conceptAlignments | many_to_one |
| ChangeProposal → DependencyAssertion | target / proposals | many_to_one |
| RevisionEvent → DependencyAssertion | target / history | many_to_one |

선행 관계의 의미는 방향을 갖습니다. Foundry가 링크 양쪽 탐색을 지원한다는 사실과 관계의 대칭성은 다릅니다. 관점·조건·근거가 있는 DependencyAssertion은 메타데이터를 가진 관계를 연결 객체로 두는 공식 패턴의 수학 도메인 응용입니다. [Link types](https://www.palantir.com/docs/foundry/object-link-types/link-types-overview) · [Object backed links](https://www.palantir.com/docs/foundry/ontology/ontology-structural-guidance)

## 행동 계약

| 행동 | 효과 | 승인 |
| --- | --- | --- |
| ProposeDependencyChange | create proposal without changing selected graph | not_needed_for_draft |
| ApproveAndApplyDependencyChange | update current assertion and append RevisionEvent together | explicit_user_approval_required |
| RejectDependencyChange | record rejection and preserve selected graph | explicit_decision_required |
| RestoreDependencyRevision | append compensating revision preserving previous history | explicit_user_approval_required |

실제 승인 반영과 복원은 정확한 변경 내용의 승인, expectedRevision과 expectedGraphRevision의 일치, 참조 타입·무결성, 관점 범위, 필수 선수 DAG 검증을 통과하도록 설계합니다. 전체 그래프 리비전 검사는 다른 관계의 동시 변경도 감지하기 위한 계약입니다. 현재는 설계 계약이며 운영 집행 장치가 아닙니다. [Action types](https://www.palantir.com/docs/foundry/action-types/overview) · [Submission criteria](https://www.palantir.com/docs/foundry/action-types/submission-criteria)

KnowledgeElement 인터페이스는 개념·용어·기호의 공통 속성을 표현하는 선택적 계약입니다. Foundry의 언어·도구별 지원이 다르므로 이 인터페이스의 실행 지원을 MVP 전제로 두지 않습니다. [Interfaces](https://www.palantir.com/docs/foundry/interfaces/interface-overview)
