# 관계 변경 제안 샘플

관계는 대화로 수정하는 주장 단위로 관리합니다. 개념 ID를 유지한 채 관계의 유형·근거·조건·관점을 따로 버전 관리하는 작은 샘플입니다.

여기의 변경 제안은 가상 예시이며 사용자가 실제로 요청하거나 채택한 관계 변경이 아닙니다. 현재 개념 지도 원본 r2의 관계를 바꾸지 않습니다.

## 관계 주장의 필드

EdgeAssertion은 안정된 ID, 시작·도착 개념, 관계 유형, 이유, 적용 조건, 근거, 상태, 관점을 각각 보관합니다. 수학적 조건에서 나오는 요구와 특정 설명·교수 관점의 요구를 구분합니다.

## 가상 변경 비교

분수 덧셈 → 유리수 덧셈

현재 미리보기: 관련 개념

가상 대안: 도움되는 선행

이유: 양의 분수에서 공통 단위를 이해한 경험을 부호 있는 유리수로 확장하는 설명에 사용할 수 있습니다.

사용자 결정: 요청하지 않음. 원본 변경: 없음.

## 이력과 무결성

채택·제안·폐기 상태와 대안을 보존합니다. 변경 제안은 이전 값과 새 값, 이유, 사용자 결정, 영향 범위를 따로 남깁니다. 이 샘플의 기존 관계도 확정된 정답이 아니라 제안 상태입니다.

순환 검사는 선택된 필수 선행 관계에만 적용합니다. 다른 표현과 관련 개념의 순환을 오류로 처리하지 않습니다. 과거 스냅샷을 새 리비전으로 복원하는 절차는 설계 예시이며, 실행 가능한 롤백이나 자동 승인 기능은 구현하지 않았습니다.
