# Palantir 공식 문서와 수학 모델 대응

공식 제품 설명과 MathEducation의 설계 선택을 구분한 대응표입니다. Palantir의 문서는 플랫폼 구성요소와 제약을 뒷받침하며, 수학 관계의 타당성이나 한국 교육과정 배치를 대신 증명하지 않습니다.

## 공식 문서와 확인 내용

### Ontology overview

Objects, properties and links provide semantics; actions, functions and dynamic security provide kinetics.

[공식 문서](https://www.palantir.com/docs/foundry/ontology/overview)

### Ontology system

The operating model integrates data, logic, action and security.

[공식 문서](https://www.palantir.com/docs/foundry/architecture-center/ontology-system)

### Object types

Object types define schemas; objects are instances.

[공식 문서](https://www.palantir.com/docs/foundry/object-link-types/object-types-overview)

### Properties

A property definition differs from its value on one object.

[공식 문서](https://www.palantir.com/docs/foundry/object-link-types/properties-overview)

### Link types

A link type defines a relationship; both sides can be traversed without making its domain meaning symmetric.

[공식 문서](https://www.palantir.com/docs/foundry/object-link-types/link-types-overview)

### Interfaces

Interfaces are abstract shared shapes and capabilities; product and language support varies.

[공식 문서](https://www.palantir.com/docs/foundry/interfaces/interface-overview)

### Ontology design principles

Model domain entities; prefer composition over deep hierarchies.

[공식 문서](https://www.palantir.com/docs/foundry/ontology/ontology-best-practices)

### Structural guidance

Relationships carrying their own metadata can use object-backed links.

[공식 문서](https://www.palantir.com/docs/foundry/ontology/ontology-structural-guidance)

### Action types

Actions bundle meaningful edits; action types define those operations.

[공식 문서](https://www.palantir.com/docs/foundry/action-types/overview)

### Functions

Functions provide server-side logic for objects, links and complex edits.

[공식 문서](https://www.palantir.com/docs/foundry/functions/overview)

### Ontology edits

Edit functions can return edits for function-backed actions; preview execution is distinct from commit.

[공식 문서](https://www.palantir.com/docs/foundry/functions/edits-overview)

### Submission criteria

Criteria can govern action execution using users, parameters and object state.

[공식 문서](https://www.palantir.com/docs/foundry/action-types/submission-criteria)

### Consistency and isolation

Action edit atomicity does not include external side effects such as notifications or webhooks.

[공식 문서](https://www.palantir.com/docs/foundry/action-types/consistency-guarantees)

### Action log

Configured action logs capture successful action submissions, not every edit path or failed action.

[공식 문서](https://www.palantir.com/docs/foundry/action-types/action-log)

### Undo or revert actions

Built-in undo has immediate/latest-edit/user/storage restrictions and does not undo side effects.

[공식 문서](https://www.palantir.com/docs/foundry/action-types/action-reverts)

### Ontology branching

Branches and proposals govern ontology resource definition changes.

[공식 문서](https://www.palantir.com/docs/foundry/ontologies/branching-ontology)

### Ontology scenarios

Scenarios are beta what-if sandboxes, not historical snapshots or data-versioning tools.

[공식 문서](https://www.palantir.com/docs/foundry/ontology/overview-ontology-scenario)

### Ontology anti-patterns

Preserve one entity identity and connect history or amendment objects.

[공식 문서](https://www.palantir.com/docs/foundry/ontology/ontology-anti-patterns)

### AIP Chatbot tools

LLMs can use configured object queries, functions and actions; actions may require user confirmation.

[공식 문서](https://www.palantir.com/docs/foundry/chatbot-studio/tools)

## 그대로 가져오지 않는 가정

### 배포 상태

Foundry를 실행하거나 설치하지 않았고 플랫폼 호환성도 검증하지 않았다.

### 적용 상태

제안 파일과 모의 검증만 게시했다. 실제 지식 그래프 변경, 사용자 승인, 운영 권한 집행은 없다.

### 교육과정 근거

학년과 성취기준의 공식 매핑은 미검증이며 공식 코드 인스턴스를 만들어 넣지 않았다.

### 시나리오

Palantir Scenarios는 과거 버전 보관 도구가 아니므로 장기 복원 근거로 사용하지 않는다.

### 되돌리기

본 예시는 새 revision을 만드는 보상 변경이다. Palantir 기본 Undo의 제약과 구별한다.

### AIP

LLM 제안을 수학적 증명이나 검증된 교육 순서로 간주하지 않는다.

### 스키마

이 JSON Schema는 자체 제안 데이터 형식이다. Foundry import나 OSDK 생성물은 아니다.
